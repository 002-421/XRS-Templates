# XRS Templates — публикация из XRS

Актуальный формат: HTTPS + SHA-256, schemaVersion 3. Root, Ed25519, USB,
Actions dispatch, PR и Environment approval в обычной публикации не используются.
Предыдущий формат сохранён только для изолированных проверок совместимости;
старый signing wizard не запускается штатной командой.

На административном Windows-компьютере один раз установите Node.js 24+ и
официальный GitHub CLI 2.81+ и запустите `Setup-XRS-Templates.cmd`.
Входите как 002-421 на официальном GitHub. Credentials остаются в Windows
Credential Manager; ключи подписи и PAT в XRS не передаются.

В XRS сохраните нужную редакцию в утверждённый общий каталог. Затем нажмите
«Загрузить шаблоны», введите PIN 4–6 цифр и дождитесь проверки опубликованного
Release. Личные редакции и Draft автоматически не публикуются.
Врачи нажимают «Обновить шаблоны» и подтверждают установку.

Каталоги публикуются как неизменяемые GitHub Releases `xrs-templates-vN.N.N`:
`catalog.xrszip` и `catalog-manifest.json`. Теги резервируют одну версию,
архивы проверяются до открытия Release. После сбоя продолжается та же операция.
Защита main, Environments и updater EXE не меняются.

Модель доверия допускает компрометацию пакета вместе с манифестом при захвате
самого GitHub-источника; SHA-256 подтверждает целостность, а не независимую подпись.

Разработка: `npm ci --ignore-scripts`, `npm test`, `npm run validate`.
CI проверяет синтетические публикации. Это не утверждение медицинского содержания
и не доказательство реальной GitHub-публикации.
